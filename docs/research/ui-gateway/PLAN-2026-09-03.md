## Shape of the work

Design and planning are done at the frontier (this document, the spec and
the task contracts). Execution is handed to one Opus session by the owner
directly, using HANDOFF-OPUS-OPTION1.md. Opus executes the contracts in
dependency order, may use Sonnet subagents for UG-6 and UG-5 (the
well-fenced tooling and test work), and performs the mechanical
integration steps of UG-7 (reprojection, serve, crawl, run record). The
frontier returns afterwards for the quality review of the whole
(DELEGATION-SPEC section E) and the merge decision.

Opus commits per task on `wt/ui-gateway-option1`, locally, never pushing.
Each commit message names the task id. The tree is clean between tasks.

## Risks

- **Golden corpus drift.** The identity key changes flask and fastapi
  baselines. Expected; refreshed at UG-7 after reading the diff.
- **Reprojection cost.** VS Code reprojects in about two minutes under the
  venv interpreter; enrichment re-attaches by digest. The Homebrew python
  silently yields zero symbols; UG-7 pins the interpreter.
- **Parallel executors, one worktree.** Scope fences are disjoint and
  executors never commit. If a test run collides with another executor's
  edit, rerun rather than diagnose.
- **The flow-route label change** touches crawl O3 (labels match the
  sidecar). O3 reads the sidecar, so it holds by construction; UG-6
  confirms.
- **UnaMentis regression.** Ancestor inheritance changes group membership
  on the iOS bundle too. UG-7 compares its portrait before and after and
  the 56/56 crawl must hold.
