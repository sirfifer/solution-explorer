The finding you asked for: the map never says what this app needs to run

You stated it during the run and the source states it in one sentence. The app is standalone-first. The backend is optional, exists for organizational use, and is never required. Cloud inference, when the on-device model is not enough, goes straight from the device to the provider with the user's key. No proxy, no third party in between.

What the repository says

CLAUDE.md:19: "This is a standalone mobile app. It communicates with the UnaMentis server via HTTP REST APIs (port 8766) but has zero source-level dependencies on server code."

The self-hosted path is gated behind a settings flag. Every provider call goes direct from the device over HTTPS or WSS with the Keychain key. Nothing in the audio path traverses the backend. Ten provider key slots, nine services wired, all called from the phone.

The data model stratifies what it knows into three kinds and mostly labels them: measured counts, metrics and edges; inferred capabilities, rules and concerns carrying a confidence field; and interpreted enrichment prose and tours stamped with status and provenance. What to fix, in order

Each item names the side that owns it. generation is the deterministic parser and derivers. enrichment is model-written prose and tours. seam is the contract between data and interface. glass is the interface alone.

1
highgenerationseamglass

Make deployment posture a first-class fact

What must exist for this system to run, what is optional, and where inference happens. The source states it; the projection does not carry it; the interface has nowhere to show it. On this subject it is the most important commercial fact there is, and two runs in one day got it wrong in opposite directions.

Do: add a posture block to orientation.json (required, optional, on-device, direct-to-provider) derived from the subject's own docs and config, mark it interpreted where it is, and render it on the Overview beside the interpreted statement. Never infer "critical" from fan-in alone when the subject says otherwise.

2
highgenerationglass

Switch off the Capability and Rules lenses until they have a threshold

Both present inferred signals as inventory. On this subject the capability inventory is three parser fragments and the rules inventory is 778 switch sites. All three personas stopped using both lenses; one of them is the destination of a landing-page question.

Do: the queue_name event rule must not fire on Swift argument labels; a policy-rule signal must not fire on JSON. Until a lens has a confidence floor, hide it or label it "3 inferred event names, low confidence" rather than "3 capabilities · 0 proven by tests".

3
highenrichmentseam

No numeral, and no runtime claim, in prose that the data does not hold

"Seventeen providers", "six STT", "seven TTS", and a fallback chain the app never runs, all inside a tour that cites a commit and a file and line per step. The furniture of derivation around underived sentences is the most dangerous shape in the product, and it is the same class as the morning's "over 140 endpoints".

Do: bind counts in tours and help text to structured fields at generation time or strip them; treat "X handles failure at runtime" as a claim requiring a call site, not a declaration. Add the check to lint-projection.py so it fails a build.

The data carries confidence: inferred, status: interpreted and derived_from_commit: null. The interface renders none of them. This is the single change that turns most of the table above from trust incidents into labelled hypotheses.

Do: a visible mark on every inferred or interpreted value, in every lens, on the ledger and in tours. Same idiom as the disabled "not observed" question routes, which every persona praised.

Bottom line

For orientation, ship it. Three strangers, one who cannot read Swift, one who does not read code at all, each had a correct model of a 161,000-line application in minutes, and the executive wrote a board brief.

For citation, not with these lenses on. Every persona's condition for using the output was the same: trust the numbers, verify the sentences. That is a reasonable discipline for a skeptic and an unreasonable one to require of a buyer. Items one through four are what separate the two sentences, and none is a redesign. Item one is the fact you asked about, and it is missing from both halves of the product.
