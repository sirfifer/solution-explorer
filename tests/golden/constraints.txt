# Frozen golden toolchain (card G2).
#
# The golden corpus freezes the TARGET (corpus.lock pins the repo commit). This
# file freezes the ANALYZER's parsing toolchain that produced the approved
# baseline, so a fresh generation in CI resolves the SAME tree-sitter grammars
# and rules loader rather than whatever the project's `>=0.23` ranges resolve to
# at run time. Without this, a new grammar release could move Flask's parse tree
# and make `check` report drift with zero engine change (a false positive that
# would poison the gate).
#
# These pins cover only the packages whose version can change the diffed
# projection sections: the tree-sitter runtime and grammars (parse structure)
# and PyYAML (the project-rules loader, which feeds findings). The project's
# general dependency ranges in pyproject.toml are intentionally left as ranges
# for Dependabot; this constraints file is applied ONLY to the golden-corpus
# workflow and to local re-baselining (pip install -e ".[all,dev]" -c this).
#
# When you re-baseline (scripts/golden-corpus.py baseline <name>), regenerate
# this file from the same environment so the pins and the baseline stay in lock
# step: python3 -m pip freeze | grep -iE '^tree.sitter|^PyYAML' | sort.
#
# Honest residual: identical grammar versions produce identical parse trees
# across OS and Python minor versions (tree-sitter is a native, versioned
# parser), which the CI run on this PR confirmed against a macOS/Python 3.14
# baseline. If a future run still drifts on an environment change alone,
# reconcile by re-baselining rather than treating it as an engine regression.
